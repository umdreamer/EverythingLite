# 路线图

当前源码版本为 0.5.1。已实现的后台搜索、800 ms 防抖、IME 保护、排除规则、程序包索引和指定文件夹搜索见 [架构](ARCHITECTURE.md) 与 [搜索语法](SEARCH_SYNTAX.md)。人工交互与性能验收仍独立于这些源码实现。本路线图表达候选方向，不承诺发布日期、性能数值或必然采用某种技术方案。

## 近期方向

优先建立可复现的合成数据正确性基线和 GUI 验收记录。比较 CLI 与 GUI 时应对齐数据库、规范化输入、范围、路径匹配及分页。优化不能以遗漏已有匹配项为代价，也不能把主表对照或双路径确认理解为所有查询正确性的完整证明。

后续需在目标 Mac 上人工验收排除规则编辑、文件夹选择、离线来源范围搜索及大量索引记录下的响应时间，并记录可复现结果。

## 搜索与性能

候选能力包括大小写、整词、正则、布尔条件和可保存 Filters。扩展前应定义解析与匹配语义，并加入针对有效、无效输入的回归。

性能方向包括短词及路径查询、数据库全局排序、分页成本、结果模型规模、索引维护与统计。名称 FTS、路径索引、缓存和内存结构应按合成基准比较收益与资源成本，不预设某种结构一定更快。需要重复测量与分位数报告，现有 benchmark 尚未自动提供分位数。

## 桌面集成与分发

macOS 候选包括原生 Quick Look、打开方式选择器、文件拖放、全局快捷键及卷状态管理。高级工作流候选包括完整书签编辑器、搜索历史、预览及完整后台导出。

0.5.0 已加入按日索引更新日志、用户可选的保留期限和手动删除。搜索关键词日志仍只留在内存。结果“状态”列记录本应用被系统接受的打开请求时间，选中结果后后台核验原路径；没有本应用记录不能解释为“从未打开过”。

独立分发需要依赖部署、签名、公证、安装与升级验证。Linux 的 inotify 后端已加入开发版本，目标桌面与大目录性能仍需验收。Windows 的实时监听尚未实现，应保持 Core 共用并设计独立平台后端。正文全文检索、OCR 与语义检索是更远期候选，不作为当前版本能力。
