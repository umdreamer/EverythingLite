# Mac 与 Linux 功能一致性设计

设计状态：按统一名称 EverythingLite 进入实施。本项目采用 Vibe Coding 方式开发；设计、实现、自动测试和人工验收分别记录。

## 目标与基线

以现有 Everything Lite 0.4.11 的源代码和搜索行为为基线，增加 Ubuntu 24.04 LTS 桌面支持，兼顾 Debian 系构建。一个仓库持续维护 Mac 与 Linux 两个桌面版本，不复制版本目录、不分叉搜索算法和主窗口实现。编译产物统一采用 EverythingLite 名称：Mac 为 EverythingLite.app（内部 GUI 可执行文件 EverythingLite），Linux GUI 为 EverythingLite，CLI 为 EverythingLite-cli。名称不附加平台后缀，平台由文件格式及分发包识别。内部应用与设置标识保持兼容，避免重命名导致既有 Mac 设置或数据库失联。

本轮实现完成后两端同步使用 0.4.12，以区别新增的平台能力。现有 0.4.11 标签保持不变，当前运行中的 Mac 0.4.11 不自动重启或迁移数据库。CMake、README、CHANGELOG、发布说明、Docker 镜像标签及包版本同步更新。

一致性指相同数据与查询得到相同搜索规则和结果，以及相同的主窗口结构、菜单功能入口、设置、分页与导出规则。系统文件管理器、原生预览器、桌面主题、窗口装饰和平台标准快捷键使用各自系统的机制；不能声称 Finder 与 Linux 文件管理器、Quick Look 与 Linux 预览器具有完全相同的外观和支持格式。

## 方案选择

推荐保留 C++17、Qt 6 Widgets、SQLite 与 CMake，共用 Core、SearchService、SearchWorker、结果模型和主窗口，仅隔离文件监听与桌面操作。该方案能直接复用 0.4.11 行为，并让同一套测试约束两端。

复制独立 Mac/Linux 工程会产生两个搜索入口和两份界面维护负担，不能可靠保证后续一致性。重写为新的跨平台技术栈会扩大行为变化与迁移风险，也不能直接继承当前验证结果。本轮不采用这两种方案。

## 共享行为

普通关键词默认仅匹配名称，显式 path/Match Path 匹配路径；扩展名、大小、修改时间与类型过滤语义一致。FTS5 trigram 与可靠查询回退继续由共享 Core 决定，不在 Linux 界面中另写算法。

两端保留 800 ms 输入空闲等待、中文 IME 组词保护、Enter 查询、专用后台搜索线程、服务复用、旧结果保留、过期 request ID 丢弃和单次查询期间仅保留最新待执行状态。每批 1000 条，排序与 CSV 导出只处理已加载模型；本轮不扩展为全量结果排序或后台全量导出。

索引目录设置、书签、列布局、状态栏、诊断、复制路径、多选打开与新窗口共用现有实现。默认目录通过 Qt 系统目录接口选择，兼容 Linux 本地化的桌面、文档与下载目录。标准快捷键由 Qt 平台映射；不把 Mac 的 Command 键硬编码为 Linux 快捷键。

## Linux 实时文件监听

增加独立 Linux inotify 后端，实现现有 FileWatcher 接口。递归安装目录监听，处理新建、写入关闭、属性变化、删除、移入移出和目录重命名。索引器沿用共享事件聚合与静默刷新链路，不能因持续文件事件抢占或取消用户查询。

inotify 本身不提供递归监听；新增或移入目录必须补装子目录监听。启动安装期间的变化通过补偿扫描校正。根目录删除与重建、目录移动后的路径映射、重复或重叠根目录、符号链接、权限受限目录和停止/重启生命周期必须有明确处理，不把失效监听描述为正常运行。

事件队列溢出、监听资源不足或不可恢复错误须明确报告状态；需要恢复一致性时触发根目录补偿扫描。后台停止采用可唤醒机制，不能永久阻塞关闭窗口。测试使用容器内部独立临时目录，避免将宿主共享文件系统的行为误当作原生 Linux 监听结果。

## 桌面操作适配

主窗口与右键菜单共用功能入口。将平台桌面操作集中到小型适配组件，避免在主窗口增加多个互相漂移的平台分支。

打开所选文件使用系统默认应用。Linux 文件定位优先调用桌面文件管理器接口以选中目标，接口缺失或调用失败时打开所在目录并明确说明降级；菜单不显示 Finder 名称。Linux 的打开方式增加实际应用选择能力，桌面选择机制不可用时提供可执行程序选择，程序与文件参数分开传递，不拼接 shell 命令。

两端均提供快速查看与 Space 入口。Mac 保留原生 Quick Look 行为。Linux 优先采用可用的桌面预览服务，并提供独立的 Qt 基础预览作为回退：受限大小的 UTF-8 文本、图片与文件属性。不支持的格式明确说明并允许用系统应用打开，不将打开文件伪装成已经支持该格式的内嵌预览。预览读取与图像解码设资源上限，避免在主窗口同步加载任意大文件。

平台服务缺失、无会话 D-Bus、无默认应用或启动失败均反馈给界面。Qt 平台组件按需链接；Core/CLI 不依赖 Qt 或桌面会话。

## 构建、安装与公开材料

增加 Linux 构建、运行、诊断入口及 Ubuntu/Debian 依赖说明。CMake 必须在显式要求 GUI 的验证流程中确认 GUI 目标存在，不允许跳过后仍报告桌面构建成功。

提供 Linux desktop entry、图标与安装规则，并生成与构建架构一致的 Debian 包；依赖声明随实际产物检查。Mac 仍构建现有本地 app bundle，不把本机构建描述为已完成分发签名或公证。其他发行版以源码构建为兼容范围，不在未测试时承诺相同安装包可用。

Docker 构建上下文增加忽略规则，排除 Git 元数据、archive、宿主构建产物、数据库、日志与个人配置。Ubuntu 测试镜像包含 GUI 编译和无显示环境下的 Qt 测试入口，现有 CLI 演示仍独立保留。公开文档使用相对路径和合成数据，继续保留 MIT 与 Vibe Coding 声明。

## 验证与完成条件

Mac 与 Ubuntu 24.04 均使用 Debug 运行共享 Core 回归，保留 UTF-8 中间字节与末字节 0xA0 的测试。相同合成文件集与查询须给出一致的名称、类型、过滤、范围和分页结果；比较不包含宿主绝对路径、即时文件时间或机器性能数据。

Linux 专项测试覆盖真实 inotify 事件、新增子目录、目录移入与重命名、删除重建、停止重启、补偿扫描及错误处理。Qt 测试验证两端共用菜单入口、快捷键、模型内容和 Linux 基础预览；平台服务调用使用可控替身验证参数、失败反馈和降级，不据此宣称真实桌面服务已验收。

Ubuntu 容器须真实生成 GUI/CLI 和安装包，并执行独立数据的启动、索引、搜索及无显示 Qt 检查。当前可用 Linux 引擎为 arm64；x86_64 构建应单独验证并明确是否使用模拟执行。测试结果分别记录架构与运行方式，不把一个架构的通过结论覆盖到全部 Linux 系统。

最终报告区分源码一致性、自动验证、产物生成和人工桌面验收。没有真实 GNOME 桌面操作证据时，中文输入法、文件管理器选中、系统应用选择、原生预览、Wayland/X11 窗口交互及大数据库性能保持待人工验收，不能标记为已完全验证。

## 提交边界

设计、平台监听、桌面适配、构建安装及文档验证按阶段提交到本地 Git。每阶段先运行相关检查并审阅差异，仅暂存该阶段文件。设计记录与实现阶段分别提交；不自动更换运行中的应用，也不重写已有历史。远程推送与发布遵循仓库授权边界。
