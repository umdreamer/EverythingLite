# 隐私与公开材料

## 公开内容

仓库示例使用合成查询 `砀例甲`、`示例工匠` 与 `sample`，合成文件 `sample.txt`、`example.pdf`，以及相对路径或 `$HOME/示例`。公开文档不包含个人目录、实际索引规模、真实检索内容、个人机器性能或私人邮箱。公开账号、仓库链接与依赖官方来源可作为项目标识保留。

本地生成的数据库、配置、日志、导出文件与构建产物不是发布资料。合成输入也可能在输出中展开为宿主绝对路径，因此公开前仍需逐项检查文本与截图。忽略规则只防止常见文件被新增，不能从已跟踪内容或旧历史中自动删除信息。

## 运行时输出

仓库材料的脱敏不改变运行时搜索诊断功能。Trace 启用后可记录可执行文件、数据库与根目录路径、关键词原文、规范化文本、UTF-8、SQL 及绑定参数、结果路径和模型状态。Trace 日志不能直接上传；问题报告应在独立合成数据中复现，检查输出后仅提供必要摘要。

Trace 默认关闭也不意味着所有命令无敏感输出。`search`、`probe-search`、`db-path`、`stats`、索引进度、GUI 诊断、CSV 导出及复制路径仍可能展示本地信息。使用独立 `--db` 隔离 CLI 数据库；GUI 的数据库环境变量不会自动隔离 QSettings 的索引根目录。

## 历史重写后的协作

历史脱敏重写会改变受影响提交及后续提交标识。新历史发布后，已有克隆应重新克隆；旧副本不可直接合并或推送回新仓库，否则可能把已删除资料重新带入。尚未提交或尚未发布的工作应先单独审查，只移植确认无敏感内容的改动。

本地重写与更新远程引用不能清除他人的克隆、fork，也不能独立清除 GitHub 旧缓存或 Pull Request 引用。需要清理 GitHub 服务器缓存时，应通过 GitHub Support 提出请求；是否受理和如何处置由平台按敏感数据政策判断，不保证所有请求都能清除。若涉及凭据，应另行撤销或轮换。

依据：[GitHub Docs — Removing sensitive data from a repository](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。

## 提交前审查

检查源码样例、脚本默认参数、文档、图片、导出物、提交消息及作者信息。真实路径、日志、凭据和日常索引不能作为公开复现材料。安全问题处理见 [SECURITY](../SECURITY.md)，贡献要求见 [CONTRIBUTING](../CONTRIBUTING.md)。
