# 搜索日志与状态栏设计

状态栏从左到右固定为消息、搜索结果与耗时、同步、文件监听、搜索筛选。消息占剩余宽度，所有区域只显示一行；超出宽度的内容以省略号截断，完整文字通过悬停提示或菜单详情查看。索引更新首次未完成时显示“索引更新重试中”，最多自动重试两次；重试耗尽后显示“部分索引未更新”及范围数量。旧缓存保留，相关文件事件或手动重建可以重新触发未完成范围。统计条数读取失败不等于索引同步失败。

“目录监听正常”表示 macOS FSEvents 已监听配置的索引目录；“索引同步成功”表示最近一次文件变化已写入索引；“部分索引未更新”表示对应范围的扫描未完成，旧缓存仍可搜索但可能过期；“搜索结果 N 条 · T ms”表示已加载的结果数量和查询耗时。Mac 版将文件事件合并约 2 秒，再由界面合并 0.7 秒。重试的默认等待时间为 5 秒、10 秒，测试使用隔离的短间隔。应用自身的索引数据库及 SQLite 临时文件事件不安排同步；只有索引文件记录或来源可用状态确实变化时，后台同步才刷新当前搜索结果。

“搜索 → 搜索日志…”列出本次运行中最近 100 次搜索。每条记录包含开始时间、查询、范围、筛选、分页偏移、状态、耗时、返回数量、搜索开始时尚未更新的索引范围数量和详情；选择记录显示完整详情。被新查询替代的搜索记为取消，索引版本变化记为待重试，未索引文件夹中的搜索记为未执行。日志只保存在窗口内存中，不写入数据库、偏好设置或磁盘；用户可在窗口中清空。单纯修改输入文字而未触发搜索时，不建立记录。

验证包括：索引更新未完成不改变搜索结果与耗时区域；所有状态区单行且有宽度上限；实际扫描错误仍可在“索引状态…”查看；每次实际搜索建立并完成一条记录，取消和失败保留原因；日志上限和清空动作生效；GUI 测试不改写真实偏好设置。
