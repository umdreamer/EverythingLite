# 搜索日志与状态栏设计

状态栏从左到右固定为消息、搜索结果与耗时、索引更新、文件监听、搜索筛选。消息占剩余宽度，所有区域只显示一行；超出宽度的内容以省略号截断，完整文字通过悬停提示或菜单详情查看。扫描未完成时显示“待更新 N 个范围”，最多自动重试两次。旧缓存保留，相关文件事件或手动重建可以重新触发待更新范围。统计条数读取失败不等于索引更新未完成。索引任务运行时不反复改变状态文字。

“目录监听正常”表示 macOS FSEvents 已监听配置的索引目录；“索引同步成功”表示最近一次更新已完成；“待更新 N 个范围”表示本次运行中对应范围的扫描未完成，旧缓存仍可搜索但可能过期；“搜索结果 N 条 · T ms”表示已加载的结果数量和查询耗时。Mac 版将文件事件合并约 2 秒，再由界面合并 0.7 秒。重试的默认等待时间为 5 秒、10 秒，测试使用隔离的短间隔。应用自身的索引数据库及 SQLite 临时文件事件不安排同步。后台索引变化不会自动重跑搜索；重新提交搜索或滚动加载下一页才改变可见结果。“工具 → 索引状态”列出本次待更新范围和原因，也读取数据库中保留的未完成、离线和待核验来源。扫描未完整结束时，只能确定受影响范围，不能推断范围内每个文件的更新情况。

“搜索 → 搜索日志…”列出本次运行中最近 100 次搜索。每条记录包含开始时间、查询、范围、筛选、分页偏移、状态、耗时、返回数量、搜索开始时尚未更新的索引范围数量和详情；选择记录显示完整详情。被新查询替代的搜索记为取消，索引版本变化记为待重试，未索引文件夹中的搜索记为未执行。日志只保存在窗口内存中，不写入数据库、偏好设置或磁盘；用户可在窗口中清空。单纯修改输入文字而未触发搜索时，不建立记录。

0.5.0 的“工具 → 索引更新日志…”将索引任务开始、待更新、重试与恢复按本地日期写入应用数据目录的 `index-update-YYYY-MM-DD.jsonl`。当前待更新范围与所选日期历史分区显示；日志目录只允许当前用户访问，并从索引监听事件中排除。日志不保存搜索关键词。搜索日志仍仅保存在当前窗口内存中。

索引更新日志默认不自动删除。日志窗口可设置保留 7、30、90 或 365 天；设置跨重启生效，启动时及运行期间每小时检查一次是否跨日并清理到期文件。自动清理保留当天日志。用户也可选择日期手动删除，删除前必须确认；应用只处理自己命名的普通日志文件，不跟随符号链接，不删除其他文件。

结果“状态”列记录本应用最近一次被系统接受的打开请求时间；“本应用无打开记录”只表示本应用没有该路径的记录，不能推断文件从未由其他程序打开。记录保存在应用数据目录的 `open-history.db`，与可重建的搜索索引分离。查询记录在后台搜索线程完成，不在表格绘制时访问数据库。选中可访问的结果后，应用在后台核验原路径；本地路径不存在时显示“原位置不存在”，外置来源无法访问或原路径不存在时显示“来源不可用或原位置未找到”。离线缓存和仅云端副本继续保留原有状态；路径核验不会改写或删除索引。

验证包括：索引更新未完成不改变搜索结果与耗时区域；所有状态区单行且有宽度上限；实际扫描未完成的范围和原因可在“索引状态…”查看；后台索引变化不重置选中行；每次实际搜索建立并完成一条记录，取消和失败保留原因；日志上限和清空动作生效；GUI 测试不改写真实偏好设置。
