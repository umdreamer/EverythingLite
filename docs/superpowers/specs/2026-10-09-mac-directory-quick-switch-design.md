# Mac 文件对话框与 Finder 双向目录联动设计

本项目采用 Vibe Coding 方式开发。本设计记录已确认的产品行为及实施约束，不代表功能已经实现或原生兼容性已经验收。当前范围为 Mac；Linux 延期。

## 行为

Finder 的当前目录与其他应用标准打开、保存、选择文件夹对话框的当前浏览目录双向联动。Finder 在前台选定目录后，返回文件对话框时自动进入该目录；文件对话框在前台进入新目录后，已有 Finder 目录窗口在后台跟随。当前操作窗口保留焦点，不自动提交打开或保存，不更改正在输入的文件名。仅选择一个文件或目录条目而没有进入目录，不构成导航。

联动仅作用于最近使用的 Finder 目录窗口和当前活动的文件对话框，不将同一目录广播到所有窗口。窗口或应用切换后重新核对会话，旧请求不能写入新窗口。没有可验证的 Finder 目录窗口或标准文件对话框时不执行；Finder 的最近使用、搜索结果等虚拟视图不冒充文件系统目录。

界面提供启用及关闭入口。未启用时不启动跨应用观察；启用前检查系统辅助功能与控制 Finder 的权限，未授权时显示缺失能力。macOS 的系统权限需要由使用者通过系统界面授予，应用不能代替用户授权。目录只作为本地会话状态保存在内存中，不建立跨应用目录历史，不写入普通日志、Trace、源码或索引数据库；不读取或改写剪贴板。

## 循环、时序与失败

联动状态与原生操作分离。状态模块只处理规范绝对目录字符串、窗口会话标识、活动状态和严格递增观察序号，不探测文件系统。活动窗口的有效导航形成新的意图代次；对话框尚未活动时，Finder 的最新意图保留到返回对话框。多个变化只保留最新意图。

每个执行请求包含原始窗口、目标窗口、目标目录及意图代次。对应目录变化和成功结果作为程序产生的确认处理，不反向生成新意图；过期、重复或其他窗口的结果不更新当前请求。当前代次失败后不因重复观察无限重试。停用、窗口退出、无效目录上下文或未知活动应用取消可执行请求。原生操作的每个阶段再次核对目标窗口和代次，失去目标时停止，不向别的窗口继续输入。

原生访问放入独立辅助进程，避免其他应用未响应或网络目录卡顿阻塞搜索界面。控制器限制消息、观察与操作预算，等待真实退出后才释放辅助进程；关闭界面不在界面线程销毁仍在运行的进程。辅助进程提前分派，不初始化主索引或搜索诊断。

## 原生适配与证据边界

标准对话框通过受支持的可访问性结构识别。当前目录必须来自能证明目录导航语义的控件，不使用任意选中条目的 URL，也不将文件名、标题或相同名称当作完整目录。无法确认当前目录或安全的导航入口时不执行。

本机公开 SDK 声明 AXURL 为只读属性；不能直接修改它以导航。NSSavePanel 的 directoryURL 设置仅适用于拥有该面板的应用配置阶段，不能据此控制其他应用正在显示的对话框。当前研究已验证自有 NSOpenPanel／选择目录面板的公开 identifier 为 open-panel，NSSavePanel 为 save-panel，但不能据此声称外部 AX 树与当前目录控件已验证。

优先验证标准“前往文件夹”导航：只有当前已识别面板仍处于前台时才能请求打开导航窗口；确认新导航元素后，仅修改其目录字段及执行它实际提供的确认动作。不得向任意文本框写入路径，不以全局键盘输入、原面板默认按钮或 Return 回退。路径不插入脚本源码。Finder 使用目录窗口的 target 属性和稳定窗口标识更新，不调用 activate。

辅助功能实际授权缺失时，跨应用读取和控制无法进行运行验证。必须分别记录源码／编译检查、仅自有面板的观察和授权后外部交互验收，不能用前两项替代后一项。第三方自定义文件对话框按适配结果登记，不承诺所有软件都支持。

## 分阶段验收

先实现无系统副作用的双向状态模块，回归 Finder 到对话框、对话框到 Finder、返回焦点时应用最新目录、确认不回环、窗口会话替换、失败去重、过期结果、非法路径、停用及虚拟视图。随后在合成目录与自有标准面板中完成原生能力验证和安全导航适配，再接入辅助进程、界面开关及授权提示。最后检验双向真实导航、文件名和焦点保留、取消／保存按钮不被自动触发，以及辅助进程超时和退出行为。

本地分阶段提交，不推送远程；不更改当前使用中的应用或日常索引。完整来源索引与存储优化按原计划继续，目录联动作为独立功能验收。
