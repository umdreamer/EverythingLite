# 索引存储与空间维护

Everything Lite 通过 Vibe Coding 方式开发。存储优化以搜索一致性和离线缓存保留为验收条件，不依据文件名相同推断文件内容重复，不删除真实文件。Mac GUI 默认只维护一份活动索引，不再为每次维护新建恢复备份。

## 空间统计

```sh
everything-lite-cli --db '/path/to/index.db' storage stats
```

该命令只查询 SQLite 页统计，不创建缺失数据库，不执行格式升级、扫描来源或重建搜索索引。WAL 数据库缺少辅助文件且 SQLite 只读连接返回错误 14 时，会用不创建主库、禁止 SQL 写入与关闭时检查点的连接让 SQLite 重建辅助文件；统计连接自身不修改主库，但可能新增 `-wal`、`-shm`。并发写入者仍可能修改主库。输出为单行 JSON，schema_version 为 1，action 为 stats。storage 包含 main_bytes、wal_bytes、shm_bytes、page_size、page_count、freelist_bytes、backup_bytes、backup_count 和 total_bytes，单位为字节。文件长度统计不等于文件系统去重、压缩及快照后的独占物理占用。

主库空闲页代表 SQLite 已可复用、尚未归还给文件系统的空间。它与重复记录不是同一概念。备份统计只计同目录中以主库文件名开头、符合 `.pre-source-catalog-<数字>.backup.sqlite` 或 `.pre-storage-<数字>.backup.sqlite` 规则的普通文件及对应的普通来源凭证；`backup_count` 只计数据库副本。孤立凭证及维护锁文件不计入该统计；不把符号链接、任意同前缀文件或其他目录文件算为应用备份。统计名称符合规则并不代表备份已经通过恢复验证。

## 目录字典与紧凑名称索引

目录字典格式 `directory-v1` 将同一来源的父目录路径保存一次，文件条目保存目录编号、名称和元数据。完整路径通过兼容视图重建，不再为每条文件记录重复保存完整路径、父路径、来源根路径和折叠路径。显示名称与路径中的文件名分别保留；来源 ID、记录 ID、离线缓存及排除规则保持有效。

名称搜索索引采用 FTS5 的 `detail=none,columnsize=0`。三字符候选匹配后仍检查完整原词，避免分散出现的字符片段形成错误结果。短词、路径查询和不支持的输入使用可靠查询路径，不承诺固定压缩比例。

```sh
everything-lite-cli --db '/path/to/index.db' storage optimize \
  --backup '/path/to/index.db.pre-storage-124.backup.sqlite'
```

格式升级是显式操作，普通启动不自动转换现有索引。输入须为已完成来源目录升级的 schema 413；更早格式明确拒绝，须先使用支持来源目录的版本完成常规升级。新格式使用独立 schema 414，旧程序不能写入；这些数字是数据库格式号。重复执行已完成的格式迁移返回 `already_compact=true`，不创建另一份备份。已使用紧凑格式时，空闲页仍可通过 `storage compact` 回收。

迁移先取得写锁，再从独立只读连接创建并验证准确前态的恢复备份。新旧结构在事务内比较全部记录及派生字段；路径不能精确重建时回滚。来源修订号推进，正在执行的过期扫描不能继续回写。搜索索引重建和检查也属于迁移事务。迁移与空间整理共用维护锁，锁文件保留供后续维护复用。

输出 action 为 optimize，包含 before、after、backup_bytes、already_compact、migration_committed、vacuum_completed 和 error。提交前失败会回滚格式及数据；格式提交后 VACUUM 失败或取消，会保留有效的新格式，报告 `migration_committed=true`、`vacuum_completed=false` 和错误，不以备份覆盖活动数据库。命令仅在 error 为空时返回成功。恢复备份单独计入总占用。

## 显式整理

```sh
everything-lite-cli --db '/path/to/index.db' storage compact \
  --backup '/path/to/index.db.pre-storage-123.backup.sqlite'
```

备份必须使用不存在的新文件。维护源库和备份文件名均不得以 -journal、-wal、-shm 结尾，比较忽略 ASCII 大小写，防止与 SQLite 伴随文件重合；父目录别名也经过检查。文件创建采用独占方式，POSIX 权限为 0600，不覆盖已有备份。示例数字仅为合成值。

操作先检查可用空间，创建可独立读取的 SQLite 备份并验证完整性，然后使用 SQLite 的原生 VACUUM 整理原库，最后验证原库完整性及备份仍可读取。不会用旧副本替换正在使用的主库，也不会删除历史备份。同卷保守预留主库与 WAL 合计的三倍空间；异卷分别检查源卷两倍、备份卷一倍。实际可用空间不足或无法查询时拒绝操作。

结果 action 为 compact，包含 before、after 及本次 backup_bytes。after 会额外计入本次明确指定的备份，即使该文件在其他目录或不符合常规备份命名规则。常规 stats 不搜索这些外部文件。保留备份可能使总占用增加；只比较主库大小不能证明净节省空间。

Core API 支持通过 atomic_bool 取消，覆盖分批备份、SQLite 锁等待、完整性检查及 VACUUM。备份允许持续进展，限制无进展等待、可观察重启次数及总时限。写入冲突或取消会报告失败，不以旧备份覆盖并发提交。操作失败时保留备份文件；尚未完成验证的副本不能视为可恢复备份。SQLite 自身的原子事务负责处理 VACUUM 失败回滚。

`optimize-search` 仍仅重建名称搜索索引，与 `storage compact` 的空间整理行为不同。当前维护入口不自动删除旧备份，也不更改文件内容或来源身份。

## Mac 界面与备份清理

“工具 → 索引存储…”在后台读取统计，并分别提供“优化存储格式”和“仅整理空间”。Mac GUI 的两项操作均不创建备份；目录字典减少重复路径，VACUUM 回收空闲页，不保证固定压缩比例。维护时等待当前搜索与扫描结束，暂停新的扫描任务；文件变化和最新查询在完成后继续处理。阶段提示只表示当前步骤，不表示已完成百分比。关闭窗口会请求取消；格式迁移已提交后，取消整理不会撤销格式迁移。界面报告操作前后占用及格式迁移、VACUUM 是否完成。旧备份不会自动删除。

同一对话框可列出与主库同目录、精确命名的独立普通备份文件。列出不表示可恢复。“删除所选备份”只处理明确选中的文件，并先验证当前应用数据库、完整性及外键；允许删除最后一份备份。Core API 默认仍要求至少保留一份有本版本来源凭证、与当前主库文件身份匹配的已验证备份。凭证证明本应用曾从该文件身份建立备份，不提供防伪保证。符号链接、硬链接、目录别名、其他前缀、主库及 SQLite 辅助文件均不能选作删除目标。删除按文件进行；若取消或部分失败，已删除项及释放的字节会如实报告，不会伪装成事务回滚。清理不删除真实索引记录或被索引文件。

建立凭证前，维护会再次检查主库的文件身份；复制期间主库路径被替换时，操作停止并保留未认领的备份。凭证含本机绝对路径，属于本地运行数据，公开材料中不得包含该文件，见[隐私说明](PRIVACY.md)。

## 重叠目录与离线缓存

同一次多目录扫描先登记全部来源，再从子目录向父目录扫描。父来源跳过已经配置为独立来源的严格子目录。扫描结果写回前，在写事务内检查目录归属；扫描期间新增、移动或删除子来源时，过期结果不会写回。子来源的普通文件更新不改变目录归属。

离线或尚未成功扫描的子来源不能证明父缓存中的旧记录可以删除。父来源保留这些历史记录，待子来源建立有效缓存后再移除重叠范围。这可能暂时保留两份缓存，但不会根据同名、相同访问路径或未知设备身份合并独立来源。来源及相对路径不同的记录仍可分别检索。

## 搜索分页

结果按名称、所在目录及稳定记录 ID 排序。界面以来源 ID 和相对路径识别同一记录；不同来源但完整路径相同的记录只显示一次，优先显示已验证可用的来源。不同路径的同名记录保持独立。下一页偏移按数据库实际返回的行数推进，不使用界面去重后的行数。

每一页都检查同一个只读 SQLite 连接的 data_version。页间或查询过程中发生提交时，界面丢弃过期页并延迟重新加载，不混合不同版本的结果。监视连接不保持跨页读事务；重复追加同一页不会增加已显示的已知身份记录。界面分页重复与磁盘上的重复索引记录分别处理，界面去重本身不回收索引空间。

## 验证范围

独立合成数据库回归覆盖空闲页回收、记录及离线来源元数据保留、备份单文件恢复、取消、写锁冲突、并发提交保留、路径别名、来源替换和保留文件名拒绝。另一个 100001 行临时样本在迁移前后全部 `files` 字段及稳定 ID 的哈希相同；主库从 110198784 字节降至 19165184 字节，但保留恢复备份及来源凭证后的总量从 110231552 字节增至 129397363 字节。这是重复长目录构造的合成结果，不能推断真实索引的压缩比例。临时测试通过不代表已经整理日常索引。
