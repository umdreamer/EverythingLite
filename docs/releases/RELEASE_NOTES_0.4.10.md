# Everything Lite 0.4.10

本版针对 v0.4.9 在程序刚启动后“第一次开始输入明显卡顿、后续搜索反而较快”的体验问题。

## 根因

窗口构造完成后会立即调用一次 `runSearch()`。此时搜索框为空，程序仍会在 GUI 主线程查询并装载前 1001 条记录。用户若窗口一出现就开始输入，按键事件会与这次同步空查询竞争主线程，因此第一次输入最容易出现停顿。与此同时，GUI 每次查询都会新建 `SearchService`，其 `SearchEngine` 构造会再次运行 `Database::initialize()`，重复执行 schema/FTS 存在性检查。

## 修改

1. 启动时不再自动执行空关键词搜索；初始列表保持空白，用户完成第一次输入后才查询。
2. `MainWindow` 持有并复用一个 `SearchService`，启动阶段初始化一次。
3. 文件系统刷新在搜索框为空、800 ms debounce 正在等待、或中文 IME 正在组词时不会触发前台搜索。
4. 800 ms 输入停止后搜索、IME composition 保护和 Enter 立即搜索全部保留。
5. v0.4.8 的 UTF-8 `splitQuery()` 修复保持不变。

## 验证重点

启动程序后立即在搜索框输入“砀例甲”或“示例工匠”，输入过程应保持流畅；停止输入约 800 ms 后再执行查询。之后连续更换关键词，查询结果应保持与 CLI 一致。
