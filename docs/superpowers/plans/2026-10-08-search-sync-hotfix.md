# 搜索响应与目录同步修复计划

项目代码为 Vibe Coding 产物。本计划记录 0.4.13 开发分支中优先处理的缺陷，不代表原版本全部功能已交付。

## 修复目标与边界

持续文件变化不能无限延后增量处理或结果刷新。目录重命名和删除经完整扫描确认后，应移除已不存在的旧记录，并保留新位置。断开的来源及未完整扫描不得被解释为成功空目录。打开操作应按当前选中记录的完整本地路径构造文件 URL，保留合法字符；相同名称不能作为自动替换路径的依据。

搜索读取已准备好的数据库时，不争用初始化写锁。短查询应复用名称排序索引；子树清理应限定来源和路径范围。后台文件更新不得连续废弃用户查询。用户修改查询时可取消被替代的旧查询，保留现有中文输入和空闲提交行为。

仅使用独立临时目录和合成数据库验证，不读取真实搜索词，不使用日常索引作为测试输入。用户提供的版本 ZIP 不参与修改。修复遵循测试先行、规格审查、质量审查和本地提交；不推送远程。

## 界面与事件同步修复

- [x] 连续事件的处理计时从首个待处理事件计算；结果刷新同样不能被持续事件无限推迟。
- [x] 多来源队列溢出不得丢失其他来源；同来源内合并被祖先覆盖的路径，失败事件保留有界重试与错误提示。
- [x] 后台刷新等待当前查询结束，不替代正在执行的用户查询；取消令牌仅用于被用户替代的查询及关闭。
- [x] 缓存结果显示来源与可用状态，不以路径存在检查阻塞渲染，不把未核验误称为离线。
- [x] 在真实临时目录重命名、删除与连续事件环境中验证旧记录清理、新路径检索及选中记录打开 URL；特殊字符路径应准确往返。
- [x] 顺序执行核心和严格 GUI 回归，依次规格与质量审查，本地提交。

## 参考资料
