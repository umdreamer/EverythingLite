# 排除规则、来源目录索引与存储优化设计

## 状态与范围

本文件为 0.4.13 的待确认设计，尚未实施。当前应用版本仍为 0.4.12。项目通过 Vibe Coding 方式迭代，Mac 与 Linux 维护同一套索引、搜索和 Qt 界面代码。CLI 为 everything-lite-cli，GUI 名称为 Everything Lite，GUI 文件为 EverythingLite。

网络入口采用系统已经挂载的 SMB/NFS/NAS 目录。挂载、认证和网络协议连接由操作系统管理，应用保存目录路径与刷新策略，不保存 NAS 凭据。原有本地目录使用平台监听，周期索引为单独的目录模式，适用于网络目录及事件通知不可靠的其他文件系统。

实施分为可分别验证和提交的阶段：来源目录与记录身份、扫描完整性与排除规则、周期目录及增量合并、SQLite 存储优化、两平台 GUI/CLI 集成及回归。实现完成后同步版本、构建及相关文档；本设计的本地提交不授权后续远程发布。

## 现状依据

FileScanner::scanTree 在根目录不存在时返回零条扫描结果。IndexManager::rebuildRoot 只检查取消标记，仍会执行 deleteStaleForRoot；applyPathChange 也把不存在与部分访问错误直接解释为删除。网络目录不可用时，这些路径可能清除仍应保留的离线记录。

当前排除规则未实现。RootSettingsDialog 仅提供目录选择和删除，QSettings 保存根目录，数据库 roots 表保存扫描信息。网络服务器发生的远程变化不能依赖 Linux inotify 覆盖，周期重扫为必要的更新方式。

files 主表重复保存完整路径、父路径、名称、折叠名称和折叠路径，另有路径唯一索引和多个查询索引。名称 FTS 已采用 external-content，没有另存一份原始名称文本；其默认位置及文档长度数据仍占空间。当前普通名称查询不使用 idx_files_search_name 的 B-tree。

现有 SearchResultModel 只显示名称、所在位置、大小和修改时间，没有来源或离线状态。files.path 的全局唯一约束也不能保存两块设备在相同挂载路径留下的同名文件，来源隔离需要修改记录身份，不能仅增加界面颜色。

## 来源身份与搜索标记

索引来源分为本地、NAS、网盘、U 盘、移动硬盘；附加未分类状态，避免证据不足时错误归类。每个来源有独立持久 ID、显示名称、类型、可验证设备/共享身份、最近成功扫描时间及挂载路径绑定。来源类型允许人工指定和修正。系统可提供候选类型，但不能仅凭目录名称判断网盘，或仅凭 USB 连接判断是 U 盘还是移动硬盘。

文件逻辑身份由来源 ID 和来源内相对路径确定。完整路径是访问或展示绑定，不再是跨来源的唯一身份。两块设备使用相同挂载点和同名文件时，保留为不同记录；同一可验证设备换了挂载路径时可重绑定，不能默默覆盖其他设备的目录。设备身份不充分时保留待核验状态，绑定变更需明确操作，不以模糊识别自动合并。

来源信息集中存于 sources 表，文件只保存来源整数 ID 与相对路径，避免每条记录重复保存设备名称和来源类型。旧文件/根表需事务迁移并建立新的唯一约束；升级前备份并核对行数、来源身份、搜索与 FTS 一致性。旧记录无法确定来源时标为未分类，不能统一声称是本地文件。根配置、完整扫描、增量事件、清理和删除操作均按来源隔离。

GUI 保留原有四列，追加来源与可用状态列。来源显示类型及设备标签，例如 NAS · 示例共享、U 盘 · 示例备份盘。离线记录使用弱化样式并明确显示离线文字；同时支持按来源及可用状态筛选，不能只用颜色区分。排序、分页、CSV 导出与 CLI 可提供同样的缓存字段，保持共享搜索语义。

来源类型与文件可用性是独立信息。根状态分为可访问、离线、未核验和更新失败，附上检查时间；网盘文件的本地副本状态分为已有本地副本、仅云端及未知。已知云端占位文件不能显示为普通本地文件；无法从可靠供应商/平台元数据确认时标为未知。本地网盘同步目录可访问不等于网盘服务在线，也不代表其所有文件均已下载，检查失败不等于文件不存在。

结果展示、排序、过滤、tooltip 和图标使用本地 SQLite 与模型缓存，不能逐条调用远端 stat、QFileInfo、文件图标提取或网络请求。状态刷新由独立后台任务更新来源级状态；已知文件副本状态在扫描时记录，显示为上次核验结果，不承诺实时下载状态。离线记录仍可复制名称及最后路径；打开/定位/预览前明确显示需连接的来源，不能搜索时自动下载云端文件。

## 持久离线目录与增量更新

卸载、拔出、暂时断网和应用退出只改变可用状态，不删除文件记录、来源身份或目录配置。删除设备目录或遗忘索引必须是单独明确操作；编辑索引根时不能继续用 rebuildRoots 的旧逻辑清理所有暂时缺席的来源。排除规则由用户主动应用时仍可清除已排除记录，这与设备卸载的保留行为分别处理。

首次建立来源时进行完整扫描。后续更新比较扫描快照与既有记录，仅插入新增项、更新元数据改变项，且只在完整扫描成功并确认来源身份后删除已证实移除的项目。未变化文件不重复写入主表或 FTS，扫描时间与可用状态集中更新在来源/根元数据中。不能通过清空整个来源再插入实现增量更新。

启动时读取本地持久索引即可提供搜索，来源先标为未核验，在后台检测挂载和更新状态；不会因设备离线而等待该来源完成扫描，也不把全库重建作为启动的固定动作。重新连接同一来源后沿用已有记录并增量合并。其他来源能够继续搜索和更新。

增量数据库写入与文件系统增量发现必须区分。存在可靠变化通知时只处理受影响路径；不具备可持续变化日志、通知丢失、程序关闭期间发生变化或来源状态不确定时，允许后台完整枚举目录以比对变化，主库仍仅合并变化项。不能仅凭顶层目录时间戳就跳过所有后代检查，也不能承诺任意 NAS 无需遍历即可发现全部离线变化。

周期扫描的中间库为一次性暂存数据，完整成功后与持久目录事务合并；失败只丢弃中间库，不能损坏已存离线目录。同名文件、中文名称、相同挂载点、重新挂载到不同路径以及来源身份变化均需要独立测试。

## 排除语义

设置提供独立的排除目录清单、目录通配过滤器和文件通配过滤器；文件过滤器支持分号分隔，例如 *.tmp;*.log。空规则保持现有索引范围。可选择具体文件形成完整路径规则，具体目录规则同时排除目录本身及其全部后代。

过滤器匹配完整名称；含路径分隔符时匹配完整路径。支持 *、**、?：* 不跨目录分隔符，** 可跨分隔符，? 匹配单个有效 Unicode 码点且不匹配分隔符。支持双引号包裹分号及双双引号转义。名称比较沿用当前 ASCII 大小写折叠，非 ASCII 字节不做语言学大小写转换。路径边界须防止 sample 与 sample-other 混淆。

首版实现以上通配子集，不宣称完整复刻 Everything 1.5 的 regex:、ext:、Windows 隐藏/系统属性或所有高级过滤语法。未实现的前缀必须明确拒绝，不能被悄悄当作普通名称保存。添加目录和文件过滤器的入口采用 Everything 的设置方式。

Core 中的同一策略用于完整扫描、增量事件、目录重扫和 NAS 扫描。进入排除目录前停止递归；增量事件不能重新写入被排除项。保存规则后，根据已有记录在本地清除被排除项，包含离线目录的缓存；该动作由用户应用排除设置触发。规则放宽后，通过后续完整扫描补回项目。

索引策略存于数据库，由 GUI 与 CLI 共同读取。窗口布局、书签等界面偏好仍使用原有 QSettings。旧库无策略时默认为无排除；旧根目录配置保留兼容。异步扫描携带策略版本，过期策略生成的结果不得合并。

## 网络及周期索引

目录可选择本地实时监听或周期扫描模式。周期目录支持手工输入已经挂载的本地路径、立即扫描和配置刷新间隔；默认间隔为 15 分钟，允许关闭自动刷新，仅手动更新。间隔从上次扫描结束后计算，同一目录不会叠加多个扫描任务。

周期目录的文件系统访问放在独立扫描进程中，避免网络 I/O 长时间阻塞 GUI 或关闭窗口。进程只写入应用建立的独立临时扫描库；扫描策略、根目录及取消状态明确传入，不能使用日常数据库的默认环境位置。扫描过程中不修改主库；只有完整成功、策略版本仍有效且来源目录仍是同一挂载实例，才在本地主库事务中合并结果并清除该根的过期项。

记录来源挂载身份。Linux 结合挂载信息，Mac 结合文件系统挂载信息，校验扫描前后的挂载实例；不能仅凭挂载点目录仍存在就认为 NAS 在线。初次添加时无法验证来源的周期根保持待验证，不把空挂载点当成网络数据。设备身份检查也在扫描进程内执行。

未挂载、来源发生变化、权限失败、遍历失败、取消、超时或进程异常时，保留上次成功索引并标示离线/失败及上次成功时间。断线不能解释为远端文件全部删除。扫描已完整成功且来源校验通过时，空目录可成为真实的空结果。扫描中途失败允许记录诊断，但不合并暂存记录或删除旧项。

扫描控制器提供取消和有限终止等待，失败进程未退出时不启动该目录的重复扫描。操作系统中的不可中断网络 I/O 不能被应用承诺立即终止；界面必须保持可响应并报告状态。周期目录不安装递归 inotify/FSEvents 监听。

## 索引体积优化

优先保留标准 SQLite 文件格式，采用 detail=none、columnsize=0 的紧凑名称 FTS，移除当前查询没有使用的名称 B-tree，并提供显式整理空间入口。紧凑索引以三字 Unicode 片段生成候选，并用主表 instr 校验原词，避免片段分散出现形成假阳性；长词、短词、ASCII 折叠、中文、标点及 UTF-8 边界与可靠搜索路径对照。不支持安全分片的输入走可靠路径。

新库可直接使用紧凑格式；旧库只在显式优化操作中升级。先做空间检查及可恢复备份，在后台事务内重建 FTS、更新格式元数据及触发器，通过一致性检查才提交；失败保留原格式。优化后的格式元数据决定查询方式，不能让旧查询表达式访问紧凑 FTS。操作期间暂停该进程的索引写入，外部写入锁冲突应明确失败。

GUI 与 CLI 提供数据库状态和整理入口，展示主库、WAL、空闲页估算和操作前后字节数。整理包含名称索引合并、WAL 检查点及 VACUUM；VACUUM 是空间整理，不保证数据库必然缩小，也不等同于压缩归档。备份单列占用并允许用户在确认升级可用后移除，不把备份隐藏在节省比例之外。

进一步将重复父路径拆为目录字典可能节省更多空间，但涉及主表和路径查询重构，作为独立后续评估，不混入本次迁移。首版不更换为自定义压缩存储引擎，不承诺实际索引固定压缩比例。

## 合成存储实验

2026-10-03 使用 Python SQLite 3.53.4，在独立临时目录生成 20000 条合成 NAS 路径记录，按当前 files 模式、索引和 external-content trigram FTS 建库并 VACUUM。该实验不读取或修改日常索引，也未代表目标平台的真实文件系统负载。

当前结构为 16150528 字节。仅 columnsize=0 为 15962112 字节。detail=none、columnsize=0 为 14692352 字节，但直接执行现有长词 MATCH 复现 phrase queries are not supported。采用紧凑 FTS 并移除名称 B-tree 后为 13578240 字节，较当前合成库减少 15.93%。五项合成查询使用片段候选加 instr 校验，与主表直接查询的结果数量一致；这不是完整实现或完整兼容性验证。

上述数据库均已关闭并随临时目录删除。比例只适用于该合成数据、模式和 SQLite 环境，不能外推为用户数据库的压缩率，也没有据此宣称性能改善。

来源目录与记录身份迁移会改变主表和索引模式，因此上述旧模式参数实验不能作为 0.4.13 总体体积指标。完成来源改造后必须重新对照测量主库、WAL、备份及临时扫描库；持久保留更多离线来源增加的记录也须纳入总体占用。

## 验收与失败场景

排除测试覆盖具体目录和文件、通配符、中文 ?、分号与引号、路径边界、增量重建防回流、规则增删和离线记录清理。扫描测试覆盖根缺失、权限失败、扫描中途失败和取消，完整性标志必须控制清理行为。

周期索引测试使用独立目录和扫描子进程，覆盖新增、删除、断开/恢复、挂载身份变化、超时、取消、异常退出、过期策略、队列去重与窗口关闭。Linux 可以在隔离环境增加实际 NFS/SMB 挂载检查；没有真实挂载验证时只能报告合成行为通过，不能称实际 NAS 已验收。

来源目录测试覆盖两设备共用同一挂载点与同名文件、同一设备换挂载点、身份不足或变化、拔出/退出后记录保留、连接后差异合并及明确遗忘来源。未变化扫描须验证没有主表/FTS 项目写入；扫描失败不能删除旧记录。搜索断言来源、离线、未知以及云端副本状态，并验证模型所有角色均不访问文件系统。云端供应商未做真实验证时，不能宣称支持其占位文件自动识别。

存储测试覆盖旧格式、新格式、显式迁移、失败回滚、FTS 与主表一致性、三平台 CLI 输出对照、中文两个 0xA0 位置及紧凑前后搜索集合。合成数据记录主库、WAL、备份和总占用，性能结论必须使用独立测量，不以体积推断速度。

Mac 与 Ubuntu 24.04 ARM64/模拟 AMD64 顺序执行 Debug 回归，GUI 文件必须实际生成。Qt 自动回归覆盖设置保存、错误提示、扫描状态和后台任务生命周期；实际 NAS 访问、真实中文输入法、原生桌面交互及大规模性能单列目标环境验收。
